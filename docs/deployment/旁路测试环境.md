# 旁路测试环境

本文用于验收前小修验证：在总控/管理节点另开一套前后端和测试库，不替换当前 `8181/8182` 验收服务，也不更新计算节点和终端节点的 Node Agent。

## 目标

- 生产验收服务保持不动：后端 `8181`，前端 `8182`，数据库 `task_manager`。
- 旁路测试服务使用新端口：后端 `8281`，前端 `8282`，数据库 `task_manager_test`。
- MinIO 可以共用 `http://172.16.0.254:9000`，但 bucket 必须换成 `task-results-test`。
- Registry 可以共用 `172.16.0.254:5000`；如需重建 worker 镜像，测试 tag 建议使用 `:test`，不要覆盖验收中的 `:dev`。

## 必填环境变量

旁路后端必须显式设置：

```bash
DATABASE_URL='mysql+aiomysql://USER:CHANGE_ME@172.16.0.254:3306/task_manager_test'
NETWORK_PROFILE=acceptance
PREFER_BUSINESS_IPV6=true
BACKEND_PORT=8281
MANAGER_PUBLIC_URL=http://172.16.0.254:8281
MINIO_ENDPOINT=http://172.16.0.254:9000
MINIO_BUCKET=task-results-test
PLATFORM_SCRATCH_ROOT=/tmp/manage_deploy_test
SERVICE_API_TOKEN=change-me-sidecar-service-token
AUTH_SECRET=change-me-sidecar-auth-secret
```

`MANAGER_PUBLIC_URL` 最容易漏：业务容器上报指标和结果时会读取它。旁路环境必须指向 `8281`，否则测试容器可能把结果上报到生产后端。

## 首次准备

1. 在管理节点创建测试库。

```bash
mysql -uroot -p -e 'CREATE DATABASE IF NOT EXISTS task_manager_test DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;'
```

2. 准备旁路目录。

```bash
rsync -az --delete \
  --exclude='.git/' \
  --exclude='backend/.env' \
  --exclude='backend/venv/' \
  --exclude='frontend/node_modules/' \
  --exclude='node_modules/' \
  --exclude='reports/' \
  /home/bupt/manage_deploy/ /home/bupt/manage_deploy_sidecar/
```

3. 写入旁路 `.env`。

```bash
cp /home/bupt/manage_deploy_sidecar/backend/.env.sidecar.example \
  /home/bupt/manage_deploy_sidecar/backend/.env
vim /home/bupt/manage_deploy_sidecar/backend/.env
```

4. 创建旁路后端虚拟环境并安装依赖。

旁路环境不要复用全局 Python 包，也不要把依赖装到系统 Python。建议在 sidecar 目录下单独放一个虚拟环境：

```bash
cd /home/bupt/manage_deploy_sidecar/backend
python3.13 -m venv venv-sidecar
source venv-sidecar/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
```

如果管理节点只有 `python3`，先用 `python3 --version` 确认版本不低于 3.11，再把上面的 `python3.13` 改成 `python3`。

5. 启动旁路后端。

```bash
cd /home/bupt/manage_deploy_sidecar/backend
mkdir -p /home/bupt/manage_deploy_sidecar/logs
nohup /home/bupt/manage_deploy_sidecar/backend/venv-sidecar/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8281 \
  >/home/bupt/manage_deploy_sidecar/logs/backend-8281.log 2>&1 < /dev/null &
echo $! > /home/bupt/backend-sidecar.pid
curl -sS http://127.0.0.1:8281/health
```

6. 安装并启动旁路前端。

前端依赖也安装在 sidecar 目录自己的 `node_modules`，不要复用生产目录：

```bash
cd /home/bupt/manage_deploy_sidecar/frontend
npm ci
npm run build
nohup ./node_modules/.bin/vite preview --host 0.0.0.0 --port 8282 \
  >/home/bupt/manage_deploy_sidecar/logs/frontend-8282.log 2>&1 < /dev/null &
echo $! > /home/bupt/frontend-sidecar.pid
```

如使用 nginx 发布静态目录，也可以把 `/api` 代理到 `http://127.0.0.1:8281`，静态目录指向 `/home/bupt/manage_deploy_sidecar/frontend/dist`。

## 验证顺序

1. 打开 `http://172.16.0.254:8282` 或校园网可达地址对应端口。
2. 初始化/登录旁路库用户。
3. 注册拓扑节点到旁路库，或从生产库导出只读拓扑数据后导入旁路库。
4. 重建矩阵和视频模板，确认镜像地址为 `172.16.0.254:5000/...`。
5. 先跑前端页面和接口验证，再小规模创建 1-2 个任务实例。
6. 若要跑真实容器，注意端口/GPU 仍然和生产环境共享，避免使用生产任务正在占用的端口。

## 注意事项

- 旁路库和生产库隔离后，旁路后端启动时的建表、补列、默认用户、调度恢复只影响 `task_manager_test`。
- MinIO 不需要另起一套；bucket 换成 `task-results-test` 即可隔离结果对象。
- Node Agent 不需要更新。当前近期小修主要在 Manager 后端和前端页面，不涉及 Node Agent 协议或容器启动接口。
- 如果旁路环境要跑批量测评，先清空测试库历史工单和实例，避免页面混乱。
- 如果只是验证页面文案、筛选、路由状态展示，优先使用旁路库和 mock/少量数据，不要启动真实批量容器。
