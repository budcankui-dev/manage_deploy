## 实验目录与空间策略

三台机器已创建 `zjl` 专属实验根目录，权限为 `0750`、所有者为 `zjl:zjl`。每个项目在其下建立独立目录，不要把大数据、checkpoint 和输出写入 Docker 根目录：

```text
/data-or-disk/experiments/zjl/<project-name>/
├── datasets/
├── checkpoints/
├── outputs/
├── logs/
└── scripts/
```

对应路径：

| 节点 | 推荐实验根目录 | 空间策略 |
| --- | --- | --- |
| compute-1 | `/data/hdd1/experiments/zjl/<项目名>` | 优先放模型、数据和 checkpoint |
| compute-2 | `/disk/sdb/experiments/zjl/<项目名>` | 余量最少；避免大模型和无必要的镜像缓存 |
| compute-3 | `/data/experiments/zjl/<项目名>` | 优先放多卡实验、大数据集和长时间输出 |

不要随意清理 Docker 镜像、containerd 数据或其他用户目录。清理前先记录归属、用途和回滚方式。

## 维护流程

1. 先运行 `scripts/check_test_lab_nodes.sh`，保存输出到对应实验的 `logs/`，确认 SSH、Docker、GPU 和目标数据盘。
2. 记录本次实验使用的节点、GPU、容器镜像 digest/tag、代码 commit、数据集 hash 和开始时间。
3. 通过标准化部署流程更新 Node Agent 或业务镜像，不在远端部署目录直接 `git pull`。
4. 实验结束后只清理本项目明确产生的容器、临时输出和缓存；不删除共享镜像和其他用户文件。
5. IP、账号、端口、GPU、磁盘或驱动变化后，同时更新 `ops/inventory/topology_nodes.json`、本日期化基线和论文仓库摘要。
